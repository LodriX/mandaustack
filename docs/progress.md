## Findings / Temuan

- The HTTPS gateway uses a random loopback port; a request with the public CA returned HTTP 200, so routing and TLS generation work.
- Browser access failed because the local CA was not trusted, the MandauStack hosts block was not installed, and `/etc/resolver/test` returned both `::1` and `127.0.0.1` while the gateway listens only on IPv4.
- nginx on port 8443 had not been prepared in the observed run.
- Port 443 was free. Binding `127.0.0.1:443` requires root. An unprivileged wildcard bind on `0.0.0.0:443` worked on the test machine (macOS 27), but it was rejected as an experimental/security-sensitive approach.
- A foreign root nginx on `127.0.0.1:80`, dnsmasq, `/etc/resolver/test`, and `/etc/sudoers.d/herd` were present, consistent with Herd/Valet leftovers. They must not be killed, reconfigured, or adopted.
- In the earlier macOS test the app was ad-hoc signed; that machine was macOS 27.0.1, arm64. The 2026-11-12 macOS verification ran on macOS 27.2.0 arm64. The package is still ad-hoc/linker-signed: `codesign --verify --deep --strict` reports `code has no resources but signature indicates they must be present`, and `spctl` rejects it. That is expected for an unsigned local candidate, not a valid bundle signature.
- **2026-11-12 macOS 0.1.11:** a first `MANDAUSTACK_TEST_REMOTE_RUNTIME=1 npm test` failed because the upstream FrankenPHP v1.13.4 macOS asset had been re-uploaded on 2026-11-05. GitHub's release metadata reports the new SHA-256 `8c767bc3b8d1bfac287748aff4d62ade240f7e2cd1984196e5d5a84fd3a47629` for the 201,323,208-byte arm64 binary. After updating only the hash pin, the remote runtime test passed; the binary reports FrankenPHP 1.13.4 with PHP 8.5.12.
- **2026-11-12 dependency audit:** `npm audit --omit=dev` initially reported one moderate production package (`node-forge` 1.4.2, four advisories including TLS/HTTP crash and ReDoS). Updating to `node-forge` 1.4.3 cleared the production audit; six moderate development-only advisories remain.
- **2026-11-12 macOS packaged smoke:** `release/mac-arm64/MandauStack.app` reported version 0.1.11 and wrote only to a temporary HOME. Managed Node 24.22.2 and FrankenPHP PHP 8.5.12 installed; `smoke.test` returned `INDEX_OK php=8.5.12 intl=1` through the HTTPS gateway; `/secret.txt` returned the index body, not the private marker; stopping the preview returned HTTP 503; restart preserved CA, registry, and managed PHP while leaving previews stopped; managed nginx served the same project on 8443; unlink preserved project files. `/etc/hosts` and `/etc/resolver/test` hashes were unchanged, no Keychain CA existed, and no app-owned processes remained.

Adding `--ssl-revoke-best-effort` allowed verified TLS without importing CA trust or bypassing hostname checks; the smoke test also confirmed an inaccessible private project file, HTTP 503 after preview stop, and unlink preserving project files. All generated certificates and project data were confined to a temporary fixture and removed after the test.

This is the PHP development server's index fallback, not evidence of file exposure.
