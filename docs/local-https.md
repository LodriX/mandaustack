# Local HTTPS integration

Version 0.1.10 includes an unprivileged HTTPS gateway on a random loopback port. The gateway checks the TLS server name against the HTTP Host header, looks up the exact linked `.test` domain, and forwards traffic only to a running preview at `127.0.0.1`. Unlinked sites cannot reach another project's preview. A persistent, private CA signs individual site certificates because `*.test` wildcard certificates are rejected by hostname validation. Only the public CA certificate path is shown in the application; private keys stay in its per-user data directory.

Run a project's preview in the desktop app and use the command in the README to verify routing and TLS without modifying the system. The gateway port changes on restart, and stopping the preview removes its upstream. This is not yet a browser-ready site service.

The app's **Review .test hosts plan** button (or `npm run cli -- hosts:plan`) reads the system hosts file and proposes a dedicated, sorted MandauStack block for linked projects. The planner refuses malformed blocks, duplicate domains, mixed line endings, or a requested domain already assigned outside the managed block. It preserves unrelated entries and supports a stale-plan checksum. The writer makes a private root-owned backup under `/var/db/mandaustack/hosts-backups` before atomically replacing `/etc/hosts` and can restore that backup only if the file still matches the applied version. On macOS, **Install reviewed .test entries** runs the packaged Electron binary in Node mode via the built-in `osascript` administrator prompt; the helper accepts only the reviewed checksum and domains from the application registry. **Restore previous hosts file** requires another authorization. Neither operation runs on app startup. The macOS authorization path still needs a real privileged machine test; its file manipulation and an unprivileged packaged-style AppleScript command were tested without changing `/etc/hosts`. Windows system hosts installation is disabled until ACL-preserving replacement is available.

On macOS, **Trust local CA in user Keychain** explicitly imports the public CA using SSL-only user trust and checks a site certificate with macOS certificate verification. Before installation it refuses to adopt an existing CA. A restricted recovery record stores the exact SHA-256 fingerprint and original user Keychain path. **Remove MandauStack CA trust** uses that record to remove the corresponding SSL trust setting and certificate by fingerprint; it does not remove any private key or other certificate. Interrupted removal leaves the record for another attempt. Neither action runs on startup. The Keychain operations were tested with a simulated command runner and an untrusted CA was checked using the real, read-only macOS verifier; an actual authorized install/removal still needs testing on a dedicated machine.

The desktop **Review nginx configuration** action shows the full per-site TLS proxy file before any changes. On macOS, **Validate and prepare reviewed configuration** generates the site certificates, validates a staged configuration using managed or locally installed nginx (`-t`), then atomically saves it in the MandauStack user data directory with a previous validated version for recovery. **Start managed nginx** checks that loopback port 8443 is free, validates the current configuration, launches a separate foreground nginx process and checks HTTPS with the public local CA before reporting success. **Stop managed nginx** terminates it, and normal app exit also stops it. A failed start restores the previous validated configuration if one exists; an unexpected exit is reported. Preparation and restore require the process to be stopped. Neither operation modifies system nginx settings, DNS, or trust store. Tests run the compiled managed nginx with verified TLS and PHP routing, a deliberate crash and a port collision in temporary directories. Port 443, in-place reload and recovery from an app crash still require implementation.

To reach the target `https://project.test/` on both operating systems, the following must still be implemented and tested:

1. Test the pinned official Windows nginx binary and lifecycle on Windows x64, and validate the source-built macOS binary on a clean macOS 14 machine with Apple Command Line Tools. Configuration reload while running and app-crash recovery still need implementation.
2. Test the macOS authorization flow, backup and recovery on a dedicated machine, then implement and test a Windows authorized installer that preserves original ACLs. Linked-site changes require explicit reapplication of the reviewed plan; they are not written automatically. A wildcard DNS responder can be considered later.
3. Serve on HTTPS port 443 with port-collision checks and a reversible privileged binding mechanism on both OSes. Only after the listener is healthy should the app expose a browser-opening `.test` action.
4. Validate the macOS user-Keychain CA installation, SSL trust result, restart and removal on a dedicated machine; implement the corresponding explicit trust integration for Windows. Never export or install the CA private key.
5. Exercise actual Laravel pages, assets, redirects, uploads, updates, restarts, and deliberately failed configuration on clean macOS and Windows machines. Test both trusted and untrusted scenarios.
